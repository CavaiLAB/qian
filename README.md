# Qian

[匠心智能体平台](https://github.com/CavaiLAB/jiangxin)的前端框架。TypeScript 与 React：设计令牌、组件库、应用外壳、微前端、由 Schema 驱动的界面。

> **状态：迁移进行中（2026-11-17）。** 代码正在从 [`idadawn/qian`](https://github.com/idadawn/qian) 的前端工作区迁入本仓库，迁移过程中由 **yue** 更名为 qian。计划与进度见[迁移与更名](docs/migration.md)。导入合入之前，本仓库只有框架级文档。
>
> **名字说明：** 2026-11-17 之前，「Qian」指基于 Kun 的平台层（`idadawn/qian` 仓库里的后端、`Qian.*` 包）。那部分后端并入 [Kun](https://github.com/CavaiLAB/kun)，「Qian」今后只作前端框架的名字。读旧文档时注意区分。组件 id 前缀 `qian.`、`qian` 命令行这些保留下来的字面，不表示前端框架。

## 定位

Qian 负责人看得见、摸得着的那一层。在平台的理念「三元全智生命体」里，它和 Kun 一起构成「三元」，也就是躯体；人在这里提出意图、查看过程、判断结果、审核智能体的往来。

它有两个使用方式：

- **当组件库用。** 装几个包，在自己的 React 项目里用设计令牌和组件。
- **当应用框架用。** 用应用外壳承载整个产品，业务页面作为远程模块按需加载，表单和列表由 Schema 渲染。

## 设计原则

1. **分层，下层不引用上层。** 包之间允许的依赖写在一张矩阵里，违反即检查失败，不接受「先引用、以后再改」。
2. **界面由数据描述。** 表单与列表由 Schema 渲染。智能体要改界面，改的是 Schema，不是前端代码。
3. **外壳也是一棵插件树。** 前端有一个与后端同语义的运行时，页面、菜单、控件都是带范围的注册，可以按租户遮蔽。
4. **浏览器里不放令牌。** 会话由网关持有，前端只带会话 Cookie。
5. **可访问性与性能有预算。** 可访问性检查不过、首屏脚本超出预算，都不能合入。
6. **组件不写死文案。** 面向用户的文字由宿主经国际化传入。
